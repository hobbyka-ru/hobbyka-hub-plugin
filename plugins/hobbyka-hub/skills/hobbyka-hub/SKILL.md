# Hobbyka Hub

Работай только при подключённом профиле VPN Хоббики. Плагин сам использует внутренний адрес Hub и доверенный сертификат; `HOBBYKA_HUB_URL` нужен только для локальной разработки.

## Установка

1. Возьми точный slug из просьбы сотрудника.
2. Выполни `node <plugin-root>/bin/hobbyka-hub.mjs install <slug>`.
3. Сообщи успех только если команда завершилась с кодом 0. В этом случае Hub уже зарегистрировал установку.

Установка автоматически включает проверку обновлений каждые 15 минут. Обновляются все установленные плагины marketplace `hobbyka-hub`, которые Codex возвращает через `plugin list`. На macOS используется пользовательский LaunchAgent, на Windows — Task Scheduler.

Ручная проверка: `node <plugin-root>/bin/hobbyka-hub.mjs update`.

Управление фоновым обновлением: `node <plugin-root>/bin/hobbyka-hub.mjs autoupdate enable|disable`.

## Публикация

1. Проверь, что выбранная папка — один законченный Codex-плагин с `.codex-plugin/plugin.json`.
2. Выполни `node <plugin-root>/bin/hobbyka-hub.mjs publish <absolute-plugin-directory>`.
3. Перед перезаписью существующей версии покажи автору найденные `name` и `version` и получи подтверждение.

## Предложение изменения

1. Подготовь исходники: `node <plugin-root>/bin/hobbyka-hub.mjs propose <slug> [absolute-directory]`.
2. Внеси изменения в созданную папку и проверь плагин локально.
3. Покажи сотруднику краткое резюме изменений и получи подтверждение отправки.
4. Создай PR: `node <plugin-root>/bin/hobbyka-hub.mjs propose <absolute-directory> --submit`.

GitHub-аккаунт сотрудника не нужен: автор предложения определяется по VPN-профилю, ветку и PR создаёт сервер ХАБа.

Если после подготовки исходников вышел новый релиз, ХАБ просит GitHub перенести предложение на него. Совместимые изменения попадут в PR автоматически; при конфликте PR сохранится для разбора агентом, а локальная папка останется без изменений. Не повторяй отправку после уже созданного PR.

Не выводи VPN-конфигурацию, токены и заголовки шлюза.
